Methodology this ledger inherits

  • Never trust the agent's own final text as evidence. Every closed cluster above was verified by calling the underlying Python builder directly with the same args the agent used, and comparing.
  • A single clean run is not proof. Cluster M found a 1-in-3 failure rate on an identical question; Cluster R deliberately re-tested "esse mês" 3x across different phrasings before declaring it unbroken.
  • Trace-level evidence over transcript-level evidence where available. Clusters K onward pull real Langfuse traces (tool ac40dc6 added tracing); E-J relied on NDJSON telemetry (ENABLE_AGENT_TELEMETRY=true) instead, since Langfuse didn't exist yet at that point in the campaign.
  • The tool/SQL layer has been correct in every cluster this ledger tracks. Every closed defect lived in final-answer synthesis — a right number relabeled, silently rescoped, or misdated. Distrust the last sentence more than the JSON payload it was built from.

Hard constraints (non-negotiable)

  1. Never relabel a substituted metric with the asked-for name — disclose the gap.
  2. Never present partial coverage as complete — name what's missing.
  3. Never resolve relative dates by reasoning — pin them in Python.
  4. Never guess portfolio names — only use names that came from a tool result.
  5. Never aggregate across banks silently — sum explicitly or disclose the skip.
  6. PARCELA = 0 is the first installment. Never normalize to 1.
  7. ID_REC_STATUS = 5 is "Exceção" in business terms, not 11.
  8. STATUS_GERADOS = (1, 2, 3, 10, 12) — never relabel this set.
  9. The tool layer has been correct in every cluster to date. The failure is in synthesis. Act accordingly.
